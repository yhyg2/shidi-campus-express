# 依赖审计

检查日期：2026-10-25。本地环境为 Node.js 24.22.1，使用 npm 的公开已知漏洞数据库进行检查。

## 固定版本

| 范围 | 版本 | 说明 |
| --- | --- | --- |
| wx-server-sdk | 4.0.2 | 从原项目的 2.6.3 升级；精确固定直接依赖 |
| @cloudbase/database | 1.5.1 | 在 node-sdk 的传递依赖范围设置 override，去除旧版辅助依赖告警 |
| axios | 1.20.0 | 在 node-sdk 的传递依赖范围设置 override，替换存在告警的旧 HTTP 依赖 |

版本及完整依赖树见云函数目录的 `package.json` 和 `package-lock.json`。不要只复制根目录清单而丢弃云函数的锁文件与 overrides。

## 实测结果

- 原 SDK 2.6.3 解析依赖后：17 项告警（3 critical、7 high、7 moderate）。
- 仅升级 SDK 4.0.2 后：仍有 6 项传递依赖告警。
- 使用上述 overrides 和锁文件重新安装后：`npm audit --omit=dev` 返回 **0 项已知漏洞告警**。
- 真实 SDK 可加载；数据库、事务、身份与存储 API 存在；文档读写与事务结果适配检查通过。这些检查不发起云服务请求。

## 兼容性边界

HTTP 依赖跨了主版本，数据库依赖也更新了次版本。现有云函数本地回归与 SDK 适配检查已通过，但不证明真实云调用、存储签名、内容检查或消息推送已兼容。正式部署前必须在隔离云环境回归。

安全公告会变化；0 项已知告警不等于不存在漏洞。更新依赖后重新运行测试、SDK 检查和真实云回归，不要仅依靠审计数字决定上线。

```bash
npm ci --ignore-scripts --prefix cloudfunctions/api
npm run sdk:check
npm audit --omit=dev --prefix cloudfunctions/api
```
