# 导入与部署

## 本地演示

1. 安装 Node.js 22 或 24，运行 `npm test`、`npm run check`、`npm run release:check`。
2. 微信开发者工具中导入项目根目录。`project.config.json` 的 `miniprogramRoot` 指向 `miniprogram/`，`cloudfunctionRoot` 指向 `cloudfunctions/`。
3. 默认 `appid` 为 `touristappid`。工具不支持游客模式时，使用自己的测试 AppID；该改动只在本机保留。
4. 保持 `miniprogram/config.js` 的 `CLOUD_ENV` 为空、`DATA_SOURCE` 为 `auto`。首次同意协议后进入本地演示。
5. 我的 → 本地演示工具可切换角色和重置虚构数据。该操作不代表真实微信认证或云端权限。

## 云端部署

云端接入需要部署者自己的微信小程序与云开发环境。平台资质、服务类目、费用、运行时和审核要求以官方控制台为准。本仓库未验证某种注册主体必然可以上线。

1. 使用自己的正式或测试 AppID 导入项目，创建云环境。
2. 只在本地修改 `project.config.json` 的 `appid` 和 `miniprogram/config.js` 的 `CLOUD_ENV`，可将 `DATA_SOURCE` 设为 `cloud`，避免误用演示数据。不要把这些个人部署标识提交到公开仓库。
3. 本地安装云函数锁定依赖：`npm ci --ignore-scripts --prefix cloudfunctions/api`。通过开发者工具上传 `cloudfunctions/api`；采用云端安装方式时，确认其遵循提供的锁文件，并核对实际安装版本。
4. 选择平台支持的 Node.js LTS 运行时，确认 SDK 加载、数据库事务和内容安全 API 可用。此处需要真实云环境验证。
5. 调用配置接口后检查集合：`users`、`orders`、`settings`、`invites`、`logs`、`complaints`、`rate_limits`。若自动创建失败，由部署者在控制台建立集合，再排查服务端权限。
6. **将所有这些集合设置为客户端不可读写。** 云函数使用服务端权限访问，客户端不得直连读写业务集合。
7. **将云存储设置为仅创建者可读写。** 截图上传路径为 `orders/<当前账号标识>/<文件名>`。接单代取、下单人和管理员读取订单图片时由 `image.urls` 云函数核验订单权限并生成短期链接。不要使用所有用户可读规则。
8. 使用虚构数据分别验证普通用户、代取和管理员的权限后，再考虑小范围试用。

## 首个超级管理员

初始化不是“谁先点谁就是管理员”。未配置服务端变量时，云端初始化会被拒绝。

1. 用部署者微信访问小程序并同意协议，创建自己的 `users` 文档。
2. 只在私有的云开发数据库控制台查看属于该微信账号的用户文档 ID，确认选中的是自己；不要把 ID 放到公开截图或仓库。
3. 在云函数运行配置的环境变量中设置 `BOOTSTRAP_ADMIN_OPENID`，值为上一步确认的用户标识。不要写到客户端或源码中。
4. 更新函数运行配置，重新进入小程序。只有指定账号的配置响应才允许显示初始化入口；在我的 → 管理后台执行初始化。
5. 确认账号为超级管理员且 `settings/main.bootstrapUsed` 为 `true` 后，删除环境变量。
6. 后续管理员通过一次性成员邀请码加入。不要通过清空管理员标记的方式开放初始化；恢复权限应由能访问云控制台的部署者谨慎处理。

## 运营配置与消息

- 默认校区、驿站与账号都是虚构数据。运营者在管理后台配置自己的名称、楼栋、客服与价格。
- 完整地址不对未接单代取展示；配置楼栋后大厅只展示楼栋。
- 模板 ID 默认留空。在小程序后台申请模板后，将 ID 与字段映射同步配置到云函数；未配置时不发送消息。
- 下单、昵称和文字评价等操作使用平台文字内容安全接口。接口未开通或故障会拒绝相应写入，应排查权限和实际返回格式。
- 图像内容审核、保留期限清理、账号删除和运营恢复流程需要另行完善。

## 联调与上传

先使用虚构数据完成下单 → 他人接单 → 取件 → 送达 → 确认 → 评价/投诉，并从无关账号尝试访问订单和图片，确认返回拒绝。验证完成后，再按微信控制台的当前流程上传体验版并添加体验成员。

本仓库没有替部署者完成云平台配置、费用开通、资质审核或真机验证。数据库和存储权限不能仅靠源码自动保证。
